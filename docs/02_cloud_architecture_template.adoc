== Context

In the previous workshop, students implemented a first executable version of Digi Bank as a modular monolith based on Jakarta EE, PostgreSQL, Maven, and WildFly. The goal of this step was to transform the architectural framework developed in the initial work into a structured, coherent technical implementation that students could directly manipulate.

This workshop follows the same functional scope and pedagogical approach, but with a different application development stack. This time, the Digi Bank application is developed using Spring Boot, while retaining Maven, PostgreSQL, WAR packaging, and deployment on the WildFly application server. This choice allows students to compare two technical approaches applied to the same business problem, without altering the functional objectives of the Digi Bank project.

The pedagogical value of this workshop is twofold. On the one hand, it allows participants to consolidate their understanding of a modular monolithic architecture in a modern Java environment. On the other hand, it demonstrates that the same system can be implemented with different technical frameworks while maintaining the same requirements for modularity, persistence, API exposure, testability, and deployment.

== Scenario

Digi Bank's technical team now wants a second reference implementation of the system, this time based on Spring Boot. The goal is not to change the business scope or redefine the functional areas, but to rebuild a coherent first version of the banking platform using the Spring ecosystem, including Spring Boot, Spring Web, and Spring Data JPA.

The system must remain organized around the areas already identified in the core project: customer management, account management, transaction management, compliance controls, and the application entry point. The application must use PostgreSQL for data persistence, Maven for build management, be compiled in WAR format, and then deployed on WildFly as an external runtime container, following a traditional Spring Boot application deployment approach.

Your role is to produce a first stable, executable, and structured technical version of Digi Bank in Spring Boot, directly usable in IntelliJ IDEA or Visual Studio Code. This version must allow you to create the initial business components, configure data access, expose REST endpoints, validate system behavior through unit tests, and prepare a clean foundation for subsequent workshops.

== Workshop objectives

At the end of this workshop, the student should be able to:

* A3.1: Set up a Java development environment compatible with Spring Boot, Maven, PostgreSQL and WildFly.
* A3.2: Create and configure a multi-module Maven project for Digi Bank.
* A3.3: Structure a modular monolithic Spring Boot application around the domains shared, customer, account, transaction, compliance, index and app.
* A3.4: Configure PostgreSQL and WildFly to run a Spring Boot application packaged as a WAR file.
* A3.5: Develop JPA entities, repositories, services and REST controllers with Spring.
* A3.6: Produce a WAR package compatible with deployment on WildFly using SpringBootServletInitializer.
* A3.7: Write and run JUnit unit tests.
* A3.8: Write and execute BDD scenarios with Cucumber.
* A3.9: Deploy the application on WildFly and verify that it is working correctly.

    private CustomerRepository customerRepository;

    @InjectMocks
    private CustomerService customerService;

    @BeforeEach
    public void setUp() {
        MockitoAnnotations.openMocks(this);
    }

    @Test
    public void testGetCustomerById() {
        Customer customer = new Customer();
        customer.setId(1L);
        customer.setFirstName("John");
        customer.setLastName("Doe");
        customer.setEmail("john.doe@example.com");

        when(customerRepository.findById(1L)).thenReturn(Optional.of(customer));

        assertEquals("John", foundCustomer.get().getFirstName());
    }
